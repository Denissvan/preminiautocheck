# 放料失败后的二次回检状态修复

## 背景

工站放料飞拍失败后，模组会被放回料盘，夹具实际无料。现有流程在放料飞拍开始时已创建二次回检批次，失败放回路径未撤销该批次。后续运行因此对空夹具执行 `WsMod_Shp`，触发二维码无法识别并阻塞正常取放料。

## 目标

仅为实际成功留在夹具中的模组保留待二次回检状态；飞拍失败并成功放回料盘的模组不得进入恢复回检。

## 设计

1. `FlyToWs` 与 `FlyToWsaction` 仍在启动飞拍前登记回检批次，以维持停止时可恢复的现有行为。
2. `DwCamErrPalceBack` 成功将某个吸头的模组放回料盘时，按该吸头的 `XtMd.Num` 撤销对应待回检项，同时移除 `FeedBackWs` 中的对应快照。
3. 若同一批次其他模组仍已成功放入夹具，其待回检项保持不变，恢复运行仍优先回检这些项。
4. 若失败放回后该批次没有待回检项，恢复运行直接进入正常取放料，不再对夹具触发 `WsMod_Shp`。

## 验证条件

- 批次 `{1, 2}` 中撤销 `1` 后，`1` 不再待回检，`2` 仍待回检。
- 全部待回检项被撤销后，批次不再阻塞下一次取放料。
- UI 项目可成功编译。

## 非目标

- 不改变二维码识别算法或报警文案。
- 不改变真正已放料成功后停止、重启时的二次回检优先级。
