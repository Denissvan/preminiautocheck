# 供料盘选料追踪日志设计

## 目标

当供料盘首次拍照位置与现场预期首格不一致时，用一条运行日志区分以下原因：

1. P0 已经不是可取状态，或被永久/临时禁用；
2. 当前上下料模块进入了反向选料分支；
3. 运行时加载的 P0 坐标与现场配置不一致；
4. P0 可取但候选首项并非 P0，表示候选排序或筛选存在异常。

## 变更范围

仅在 `UpDownLoad.TrayPickMod` 中、供料盘候选位置生成后且调用 `XtCapMovMod` 前增加诊断日志。

不改变候选筛选、正反向排序、运动、拍照、取料或料位状态更新逻辑。

## 日志内容

每次准备从供料盘取料时，输出一条 `供料盘选料追踪` 日志，包含：

- 上下料模块号、工站号和选料方向（正序或倒序）；
- 可取候选数量；
- 实际选中位置：`idx`、行、列、模块对应的 `X/Y/Z/A` 坐标和状态；
- P0：模块对应的 `X/Y/Z/A` 坐标、状态、永久禁用和临时禁用标记。

状态为空时应明确输出“空”，避免在前一次取料后 `md` 被置空时产生歧义。

## 数据关联与判读

该日志紧邻已有的“上相机拍照”日志。现场按同一时间顺序比对即可：

- P0 不可取：状态残留或禁用；
- P0 可取、选中格不是 P0：排序/分支异常；
- P0 坐标即为非预期值：运行时配置加载异常；
- 选中格与后续“上相机拍照”的原始坐标不一致：调用链中的位置数据发生变化。

## 验证

1. 编译受影响的 UI 项目；
2. 静态检查日志位于 `XtCapMovMod` 调用之前；
3. 通过构造候选列表/P0 状态的最小测试验证日志字段能表达：P0 可取、P0 被禁用、P0 状态为空三种情况。
